## 路由页顶部路由动画（stage）补全

路由页原来缺 magpie Routing 页最上面的那块「路由动画」（`internal/gui/assets/plugins/routing/client.js` 的 stage：左 agent 列 → 中间 magpie hub → 右账号列，连线 + 沿线的 magpie 包）。本次在原生 UI 里补齐。

### 新增/改动的文件
- `internal/shell/routing_flow.go`（新，约 700 行）：整块 stage。
  - `rtFlowOf(rd, now)` 从 `RoutingData.Traces` 读出：账号（按 provider+model 去重，最多画 4）、agent（最多画 3，带请求数），以及总数（`AcctTotal`/`AgentTotal`，画不下的在脚注写「画 N」）。
  - `rtFlowModel.flights(traces, now)`：正在飞的请求（`!Done` 且 15s 内，或 `Done` 但还没落地）；一个都没有时**重放最近一次**（`now.Sub(tr.Time) % (dur+1.1s)` 循环），脚注写「重放最近一次」，包透明度降到 0.6。
  - `rtFlowAt(f, now, a0, hL, hR, stops) rtFlowMark`：把一次请求拆成「agent→hub（0~0.14）→ 逐个试的账号（0.14~0.52，失败的回 hub 再下一个）→ 等待（0.52~0.58）→ 原路返回（0.58~0.94）」；返回 `at/back/fail/hold/ok`。失败的回程是红圈（magpie 的 `.pkt.back.err`）。
  - `rtFlowPaint`（`Element.Draw` 回调）：用 `ui.Path` 的三次贝塞尔画连线（`p.StrokePath`），`p.Fill` 画圆点/光晕，`p.Stroke` 画回程的圈；`p.After(33ms)` 驱动 30fps 重绘。
  - 几何全部按常量算（列宽 156/62/132/62，agent 节点 46+8，账号行 38+6，stage 高 178），不依赖 `Bounds()`，避免父子坐标系/滚动偏移问题。
  - `rtFlowKick()`：页面在屏时每 2s 后台 `readRoutingData()` 刷新 `a.data.Routing`（`a.rtBusy` 防重入），否则 stage 只会飞开页那一刻的请求。
  - 文案：`what/whatSub/modeLine/caption/facts`，策略说明按 `rtDecision` 的中文结论给一句话（智能路由/会话亲和/容灾…）。
- `internal/shell/icons.go`：加 `iconBird`（从 `internal/gui/assets/index.html` 的 `#bird` path 提取，magpie 的鸟）与 `birdIcon()`。
- `internal/shell/app.go`：`rtFlowAt time.Time`（上次读的时间）、复用 `rtBusy` 做在途标记。
- `internal/shell/routing_page.go`：`routingView` 在 header 之后插入 `a.routingFlow(c, t, rd)`，后续段落顺延编号。
- 测试 `internal/shell/routing_flow_test.go`：合成 trace 夹具（3 agent / 4 账号 / 1 在飞 / 1 失败）、空态、重放、多包并发、容灾两跳（断言 `fail=true` 的红圈回程）、`rtFlowAt` 的位移与停留断言；`TestRoutingStageShot(s)` 写 PNG。
- `docs/screenshots/routing-stage.png`：页面成品截图。

### 经验
- MyGo 支持自绘：`Element.Draw(func(p *ui.Painter, r ui.Rect))`，`p.Fill/Stroke/StrokePath/Line` 都能用；`r` 是**父坐标系**里的盒子（不是文档说的窗口坐标），所以自绘几何用自己算的常量最稳。
- 动画两种驱动：`p.AnimationFrame()`（跟显示帧率，配 `Loop` 做呼吸点）与 `p.After(d)`（定时重绘，配 `p.Now()` 算进度，30fps 够用且省电）。
- `Loop(key, period, ease)` 会持续要帧，适合常驻脉冲；`p.After` 只在有飞行物时才调用。
